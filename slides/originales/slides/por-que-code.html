Por qué en Claude Code

Un prompt en el chat se pierde; una skill en el repo se revisa, se prueba y se hereda

Versionada con git

Va en .claude/skills/; los cambios se revisan en un pull request

Corre en su máquina

Usa su entorno de uv, sus archivos y su internet; la API las corre sin red ni paquetes nuevos

Reproducible

El script decide lo mismo cada vez; el equipo obtiene la misma base

Se puede evaluar

claude -p corre los mismos pedidos con y sin la skill, en lote

Se combina

Con MCP, hooks y subagentes (context: fork) en el mismo proyecto

Estándar abierto

Sigue Agent Skills: la misma carpeta se sube a claude.ai como zip

¿Por qué hacerlo en Claude Code y no pegando un prompt en el chat? Primero, la skill vive en el repositorio: se versiona con git, se revisa en pull requests y el que llega nuevo al equipo la hereda. Segundo, corre en su máquina, con su entorno, sus datos y su internet; en la API de Claude las skills corren en un contenedor sin red y sin poder instalar paquetes, y la ENAHO hay que bajarla. Tercero, el script hace que la limpieza sea idéntica cada vez. Cuarto, se puede evaluar con claude -p, que es lo que harán hoy. Quinto, se combina con lo que ya vimos: el MCP del BCRP, hooks y subagentes. Y sexto, es un estándar abierto, Agent Skills, así que no quedan amarrados: la misma carpeta se puede subir a claude.ai. Ojo: las skills no se sincronizan solas entre Claude Code y claude.ai; cada superficie tiene las suyas.
